# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

TERRA is an open-source AI-powered pocket compass that generates randomized walking trails. It consists of two main components:

1. **Web Application** (`/App`): Node.js Express server + HTML/CSS/JavaScript UI that generates GPS coordinate trails using AI
2. **Arduino Firmware** (`/Arduino Code`): ESP32-based embedded system that displays trails on a circular LCD with compass navigation

## Architecture & Data Flow

### Web Application Flow
```
User enters location & duration
    ↓
Frontend (script.js) constructs AI prompt with location + time constraints
    ↓
POST to /generate-trail endpoint with prompt
    ↓
Backend (server.js) proxies request to OpenAI API (GPT-4)
    ↓
Response parsed with regex to extract GPS coordinates
    ↓
config.h file generated with coordinate arrays
    ↓
User downloads config.h for Arduino upload
```

### Key Integration Points

**Frontend to Backend**:
- `script.js` line 87-95: Constructs prompt and sends to `/generate-trail`
- `script.js` line 168-207: Regex parser extracts coordinates from AI response
  - Pattern: `/(?:start point|checkpoint \d+|end point):\s*([+-]?\d+\.\d+),\s*([+-]?\d+\.\d+)/gi`
  - Works by enforcing AI to output "label: lat,lon" format

**Backend Configuration**:
- `server.js` line 18: Hardcoded `OPENAI_API_KEY` placeholder (requires manual setup)
- `server.js` line 31: Model hardcoded to `gpt-4`
- Request proxies directly to OpenAI v1/chat/completions endpoint

**Arduino Configuration**:
- `Arduino Code/Terra/config.h`: Auto-generated file containing coordinate arrays
  - Generated by web app lines 119-133 in script.js
  - Contains `startLat`, `startLon`, `stopLats[]`, `stopLons[]`, `numberOfStops`
- `Arduino Code/Terra/Terra.ino`: Main firmware reads these arrays and navigates the trail

## Running the Project

### Web Application (Node.js)

**Prerequisites**:
- Node.js v21.5+
- OpenAI API key
- Google Maps Places API key

**Development**:
```bash
cd App
npm install
# Edit server.js line 18 to add your OpenAI API key
# Edit index.html to add your Google Maps API key
node server.js
# Open http://localhost:3000 in browser
```

**Typical workflow**:
1. User enters a location (autocomplete via Google Maps)
2. Selects trail duration (5/10/30/60 minutes)
3. App generates coordinates using OpenAI GPT-4
4. Downloads `config.h` file

**Key Files**:
- `server.js`: Express server with `/generate-trail` POST endpoint
- `script.js`: Frontend logic for location input, AI prompt construction, coordinate parsing, config.h generation
- `index.html`: UI with location autocomplete dropdown and duration selector
- `styles.css`: Styling
- `package.json`: Dependencies (express, body-parser, cors, node-fetch)

### Arduino Firmware

**Hardware**: ESP32 Feather V2 with:
- 1.28" Round LCD display (GC9A01 driver)
- Beitian BN 880 GPS module
- CMPS12 compass
- Adafruit DRV2605 haptic motor controller
- Adafruit push-button power switch

**Setup in Arduino IDE**:
1. Add ESP32 board: `https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_dev_index.json`
2. Install libraries: `TinyGPSPlus`, `TFT_eSPI`, `Adafruit_DRV2605`
3. Download generated `config.h` from web app
4. Replace `Arduino Code/Terra/config.h` with generated file
5. Upload `Arduino Code/Terra/Terra.ino` to ESP32

**Debug Mode** (line 3 in Terra.ino):
- Set `bool debugMode = true` to test with manual coordinates via serial monitor
- Useful for testing without GPS fix

**Key Logic**:
- Reads GPS position and compass bearing from sensors
- Calculates distance/bearing to next checkpoint
- Updates circular LCD display with directional arrow pointing to checkpoint
- Triggers vibration haptics when approaching waypoint (within 20m) or arriving (within 10m)

## Common Development Tasks

**Modify AI Model** (OpenAI):
- Edit `server.js` line 31: Change `"gpt-4"` to another OpenAI model
- Note: Prompt is constructed client-side in `script.js` line 87

**Change Prompt Engineering**:
- Edit `script.js` line 87: Modify the dynamic prompt template
- The prompt must output in format: "label: lat,lon" for regex parser to work

**Add Different Location Service** (currently Google Maps):
- Edit `script.js` line 3-15: Replace Google Maps Autocomplete integration
- Update `index.html` line 39: Change API key or script source

**Customize Arduino Display**:
- `Arduino Code/Terra/images/`: Contains checkpoint image files in XBM format
- `Arduino Code/Terra/imagelist.h`: Lists all available images
- Convert custom 240x240px black/white BMP images to XBM using online tool, then add to images/ and imagelist.h

## Important Design Decisions

1. **Client-side Prompt Construction**: The AI prompt is built in the browser (script.js), not the server. This lets users see exactly what's being sent to the API.

2. **Regex-based Coordinate Extraction**: Instead of asking GPT-4 for JSON, the system enforces a strict "label: lat,lon" format via the prompt, then uses regex. This is more reliable than JSON parsing for this use case.

3. **config.h as Bridge**: The web app generates Arduino-compatible C++ header files. This design avoids over-the-air updates and keeps the embedded system simple.

4. **Single Model Provider**: Currently hardcoded to OpenAI. Future work should abstract the AI provider (see planned refactoring for Gemini, Claude, Ollama support).

## Planned Improvements

There is a planned refactoring to support multiple AI providers (Google Gemini, Anthropic Claude, local Ollama models). This requires:
- Provider abstraction layer and factory pattern
- Configuration system for environment variables
- Response normalization across different API formats
- Provider-specific error handling
- Optional frontend UI for model selection

## Notes for Contributors

- **No automated tests** currently exist (`package.json` has placeholder test script)
- **API keys are manual**: No environment loading currently; requires direct editing of `server.js` and `index.html`
- **Response format is rigid**: The regex parser expects strict "label: lat,lon" format; AI prompt enforcement is critical
- **Arduino has debug mode**: Useful for testing without GPS hardware
- **Coordinate precision**: Checkpoint trigger is 10m, vibration proximity is 20m (configurable in Terra.ino line 38-39)
